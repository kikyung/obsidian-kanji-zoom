# Contributing to Kanji Zoom

Thanks for helping make small kanji easier to read!

## Reporting bugs and ideas

Open an [issue](https://github.com/kikyung/obsidian-kanji-zoom/issues) with:

- what you did, what you expected, and what happened
- your Obsidian version, OS (desktop or mobile) and Obsidian language
- if possible, a small note (Markdown) that reproduces the problem

Security problems: please follow [SECURITY.md](SECURITY.md) instead of opening a public issue.

## Development setup

No Node.js or package install is needed.

```bash
python3 tools/check.py   # build + Obsidian compatibility checks + tests
```

- Edit `src/main.js` and `styles.css`. Never edit `main.js` — it is generated by `tools/build.py`.
- `data/kanji.json` is generated from KANJIDIC2 by `tools/build_kanji.py`; see `data/LICENSE-KANJIDIC2.md`.
- Tests live in `tests/plugin.test.js` and run on Node.js (CI) or macOS JavaScriptCore.
- To try your build, copy `main.js`, `manifest.json` and `styles.css` into
  `<vault>/.obsidian/plugins/kanji-zoom/` and reload Obsidian.

## Pull requests

1. Fork the repository and create a branch from `main`.
2. Keep each pull request focused on one change, and add or update tests for behavior changes.
3. Run `python3 tools/check.py` — it must pass. CI runs the same check on every pull request.
4. Describe what changed and why in the pull request.

Pull requests are squash-merged after review.

## Guidelines

The plugin follows the [Obsidian plugin guidelines](https://docs.obsidian.md/Plugins/Releasing/Plugin+guidelines).
In particular: no `innerHTML`, no inline styles (use CSS classes or variables in `styles.css`),
no network requests, no `localStorage`, and no Node.js or Electron APIs (the plugin runs on mobile too).
User-facing text lives in the `STRINGS` table in `src/main.js` in both English and Korean.
